# Notas de la Versión - v0.1.1

**Fecha:** Marzo 2026
**Enfoque:** Infraestructura, Automatización de Despliegue y Tareas Asíncronas.

## 🚀 Nuevas Características

* **Orquestación Asíncrona (Celery & Redis):** Se implementó una arquitectura basada en Workers de Celery y un Broker Redis. Esto permite delegar la carga extenuante de Scraping (GrupLAC, CvLAC, Publindex) hacia segundo plano sin colapsar el sistema.
* **Cronjob Administrable (django-celery-beat):** Se implementó un programador de tareas en la Base de Datos que lanza el recolector completo automáticamente a las 00:00 del día 1 de cada mes.
* **Semilla de Administrador Automatizada:** Creación del comando de inicialización `init_superuser.py`. El sistema ahora es capaz de leer credenciales ultra secretas desde variables en un archivo `.env` para fundar el administrador por defecto durante el proceso de Despliegue en la VPS sin intervención de consola interactiva y sin dejar rastros en git.

## 🛡️ Correcciones y Estabilidad

* **Variables Dinámicas de Peticiones:** Corrección y refactorización absoluta de los parámetros `ALLOWED_HOSTS` y `CORS_ALLOWED_ORIGINS` dentro del `settings.py` para que procesen correctamente la IP pública del servidor en producción, evitando caídas repentinas *"HTTP 400 Bad Request"*.
* **Limpieza de Artifacts de Windows:** Saneamiento estructural al archivo `requirements.txt`. Se eliminaron secuencias nulas/UTF-16 inyectadas por PowerShell al generarlo que impedían construcciones `docker build` en el sistema Debian de la VPS.
* **Compatibilidad de Scripts:** Los archivos de apoyo `.sh` (como el actualizador `redeploy.sh`) ahora fuerzan de fábrica saltos de línea bajo formato UNIX (`LF`), previniendo errores `"bad interpreter"` de Bash.

## 📦 DevOps y Arquitectura de Red

* **Renombramiento Estándar Unificado:** Todos los servicios dentro de Docker heredan el prefijo `uceva_data_vips_` de manera formal para evitar choques con otras bases de datos y garantizar la identidad del desarrollo en producción.
* **Mejora Integral en Guías (MD):**
    * Se acopló el instructivo de la instalación desde base limpia de Docker para un servidor virtual Virgen.
    * Adición de manual seguro para la configuración de un túnel SSH en DBeaver (`DBEAVER_CONEXION.md`), permitiendo al administrador inspeccionar los registros sin comprometer los puertos públicos.
